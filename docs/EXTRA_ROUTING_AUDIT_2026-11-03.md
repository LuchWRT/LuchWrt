Изменения включены в v1.2.13; [отдельный отчёт о производственных пакетах и публикации](release-v1.2.13-2026-11-03.md). Следующий текст сохраняет условия предварительных испытаний и их исходные метаданные.

Дата отчёта: 3 ноября 2026 года. Изменения находятся в исходном коде и ещё не опубликованы в стабильном выпуске.

## Удаление и освобождение места

В главном меню: **7 — Расширенные настройки → 7 — Удалить источник**.

- После сохранения и успешного применения нового набора клиент удаляет свою копию DAT, если на неё больше не ссылается ни один источник.
- Если несколько записей используют одинаковые байты, файл хранится один раз по SHA-256. Удаление одной записи оставляет файл для остальных; удаление последней освобождает его.
- При выключении дополнения источники и их файлы сохраняются для повторного включения. Для освобождения места удалите источники.
- После успешного обновления старые неиспользуемые версии удаляются. До завершения проверки/отката прежние файлы доступны.
- После отмены, ошибки в пакете источников, неверного DAT или прерванной загрузки неиспользуемые собственные файлы очищаются. Неверный файл не заменяет рабочие настройки.
- Пустой или повреждённый неиспользуемый DAT также можно удалить. Для удаления не требуется, чтобы его содержимое успешно читалось Xray.
- Исходный локальный файл пользователя вне управляемого хранилища сохраняется. Клиент удаляет импортированную копию. Посторонние имена, ссылки, каталоги, другой владелец или небезопасные права не разрешают удаление чужих данных.

В опыте с реальными загрузками после удаления последней записи каждого источника осталось **0 управляемых файлов**. Проверены сохранение общего файла до последней ссылки, сохранение копий при выключении, удаление старой версии после успешного обновления, сохранение прежней версии после неудачного обновления, удаление временных/отклонённых файлов, отказ на неверный тип и отсутствующую категорию, сохранение исходной загрузки и чужой цели символической ссылки.

## Найденные и исправленные ошибки

Все перечисленные случаи сначала воспроизведены отдельными тестами, которые завершились FAIL на прежнем коде.

1. **После удаления источника оставался пустой повреждённый DAT.** Очистка ошибочно требовала непустой рабочий файл. Теперь для неиспользуемого файла проверяются собственное имя, обычный тип, владелец и закрытые права; повреждённое содержимое не препятствует освобождению места. Успешная очистка синхронизирует каталог.
2. **Ошибка очистки после сохранения настроек скрывалась.** Теперь она выводится отдельно и различает уже сохранённое изменение и незафиксированную операцию. Успешное сохранение не объявляется отменённым; чужая цель ссылки остаётся нетронутой.
3. **Восстановление отсутствующего снимка оставляло ненужную новую версию, если URL уже изменился.** Ожидаемый SHA-256 теперь проверяется до публикации загрузки из временного файла. Отклонённая новая версия удаляется, сохранённые настройки остаются прежними. Явное обновление по-прежнему принимает новую версию после проверки.
4. **Пакетное обновление у лимита размера могло быть ошибочно отклонено.** В промежуточный размер попадали новые файлы вместе со старыми версиями ещё не обработанных URL. Теперь проверяются уже подготовленные записи и затем весь итоговый набор. Прежние файлы сохраняются для отката, но не считаются частью нового набора. Отдельный тест начинает с прежнего набора ровно на лимите 256 МиБ и обновляет его в меньший набор.
5. **Обновление не могло восстановить испорченный существующий снимок с тем же именем SHA-256.** Свежая полностью скачанная копия теперь атомарно заменяет повреждённый собственный обычный файл. Символические ссылки, каталоги, чужой владелец и открытые права при таком восстановлении вызывают отказ.

Регрессионные проверки находятся в `cmd/luch/routing_cleanup_test.go` и `internal/routeprofile/store_test.go`; перевод сообщений очистки проверяется в `cmd/luch/routing_test.go`.
