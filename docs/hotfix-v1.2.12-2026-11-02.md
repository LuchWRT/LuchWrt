# LuchWrt v1.2.12 — 2 ноября 2026 года

Исправлено сохранение ручного выбора локации. Автоматическое переключение больше не заменяет предпочтение пользователя. Исчезновение выбранного имени из очередного списка также его не стирает. После перезагрузки роутера клиент сначала использует выбранную локацию; недоступный сервер по-прежнему разрешает переход на рабочий запасной. Обычное обновление подписки сохраняет работающий запасной сервер и не вызывает постоянных переключений туда и обратно.

Формат `state.json` сохранён: `selected_name` хранит предпочтение, `config` — фактически выбранную рабочую конфигурацию. Активная локация определяется по полному подготовленному JSON, включая маршрутизацию и учётные данные. Статус отдельно показывает сохранённый выбор, если подключена запасная локация. Резервные копии и чтение настроек прежней версией сохраняют существующий формат. После обновления принимается последнее сохранённое значение: если прежняя версия уже заменила его автоматическим выбором, нужную локацию следует выбрать заново один раз. Восстановить ранее утраченную историю программа не может.

## Проверки

- `go test ./...`, проверка гонок в контроллере, агенте и CLI, `go vet ./...` — PASS. 52 проверки стенда — PASS.
- Два новых теста воспроизводят потерю предпочтения на прежнем коде и проходят после исправления.
- Официальный OpenWrt 25.12.5 ARM64 в QEMU, 256 МиБ RAM, универсальный подписанный пакет `any-arm64`: семь этапов PASS. Настройка через настоящее меню, выбор второй локации при доступной первой, обновление подписки, отказ выбранного сервера с переходом на запасной, сохранение предпочтения, настоящая перезагрузка с изменением `boot_id`, возврат ко второй локации и последующая ручная смена. Использованы настоящий Xray VLESS/TLS, контролируемая HTTPS-подписка и отдельный LAN-клиент; TCP, UDP и DNS по IPv4/IPv6 проверяются после переходов. Файл состояния и сетевые правила клиента тестовыми помощниками не подменяются.
- После публикации новая команда установки прошла на чистом официальном OpenWrt 24.10.8 x86-64: семь этапов PASS, включая совпадение восьми подписанных файлов, меню, настоящий reboot, автозапуск и удаление с сохранением посторонних настроек.

Первый адресный сетевой прогон x86-64 сохранил общий FAIL после пяти успешных этапов. После reboot проверки выбранного сервера и трафика завершились успешно, но сбор метрик не нашёл временный журнал: сборщик стенда не был запущен заново. Исправлен только этот шаг стенда; подписанные программы не менялись. Итоговый новый полный адресный PASS относится к ARM64, а публичная установка — к x86-64. Старый FAIL сохранён и не переименован в PASS. В исходном JSON шестой пункт был помечен PASS до сбора метрик; завершёнными приняты только пять этапов. Для будущих запусков запись PASS перенесена после успешного сбора всех данных.

## Комплекты и установка

Сохранены прежние 17 точных и восемь универсальных комплектов, всего 327 файлов. Для восьми семейств процессоров пересобран клиент; установщик и остальные семь файлов пакета побайтно сохранены из проверенных подписанных комплектов v1.2.11. Новые manifest и latest подписаны прежним ключом. Имена, размеры и SHA-256 всех файлов сверены до и после публикации.

В обращении по Cudy WR3000U v1/OpenWrt 25.12.5 точного текста ошибки SSH не было; позже пользователь сообщил, что установка пошла. Пересланная копия команды потеряла `||` и получила Markdown-разметку. Ошибка программы установки этим сообщением не подтверждается. В README уточнено копирование полного блока, добавлены текст команды без форматирования и [помощь с установкой](INSTALLATION_HELP.md). Проверки HTTPS, SHA-256 и подписей сохранены.

Полные новые испытания всех 17 систем не заявляются. Физический Cudy, аппаратное ускорение, общий минимум RAM и суточная работа не проверялись. Предыдущие результаты v1.2.10/v1.2.11 сохраняют свои версии.
