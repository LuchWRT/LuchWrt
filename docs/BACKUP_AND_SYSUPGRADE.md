# Резервная копия Luch и обновление OpenWrt

Эти команды доступны начиная с v1.2.10. Сначала установите этот или более новый выпуск обычной командой проекта.

Резервная копия предназначена для восстановления **того же роутера**. Она сохраняет HWID, выбранный язык, ручное отключение, ссылку подписки, имя выбранной локации и срок последней подтверждённой подписки. Полные конфигурации и каталог Xray, UUID/пароли из них, временные файлы, процессы, геобазы, старые бинарники и kernel modules в неё не входят. Доверие к времени прежней загрузки тоже не переносится.

Файл содержит секретную ссылку подписки и HWID. Это частный файл с правами `0600`, а не отчёт для GitHub или поддержки. Храните копию вне роутера в закрытом месте. Программа не печатает её содержимое и не заменяет уже существующий файл копии.

## Создать и восстановить отдельную копию

Выполняйте действия от root в SSH-терминале:

```sh
luch-install -backup /root/luch-backup.json
```

Скопируйте файл с роутера до перепрошивки. Он имеет ограниченный JSON-формат, а не произвольный архив с путями.

После установки совместимой прошивки заново установите актуальный подписанный Luch обычной командой проекта. Затем верните закрытый файл на тот же роутер, сохраните права `0600` и выполните:

```sh
chmod 600 /root/luch-backup.json
luch-install -restore /root/luch-backup.json
luch status
```

Программа проверяет формат, размер, права, владельца, тип файла, домен подписки и идентичность устройства до замены настроек. Символические ссылки, неизвестные поля/файлы, небезопасные пути и чужая идентичность отклоняются. Неверная копия не заменяет рабочие настройки. При замене настроек используются отдельная подготовленная директория и журнал восстановления; ошибка или прерывание до фиксации возвращает прежний полный набор файлов.

Если доступен аппаратный серийный номер или DMI UUID, копия содержит его SHA-256-привязку. Иначе проверяется совпадение HWID с существующими настройками. На полностью очищенном устройстве без аппаратной идентичности программа не может доказать физическое совпадение: выполняйте явное восстановление только на исходном роутере. Не разворачивайте одну копию на нескольких устройствах; для нового роутера нужна отдельная регистрация устройства.

После восстановления полных конфигураций ещё нет. Клиент должен заново получить подписку и подтвердить VPN. Прежняя отметка времени/загрузки не разрешает автономный запуск старых ключей. Если VPN был отключён вручную, пауза сохраняется; включите его через меню, когда будете готовы.

## Подготовить настройки к sysupgrade

Непосредственно перед обновлением OpenWrt:

```sh
luch-install -prepare-sysupgrade
sysupgrade -l
```

Первая команда создаёт свежий небольшой `/etc/luch/upgrade-state.json` и собственный `/lib/upgrade/keep.d/luch`. Список Luch содержит только подготовленный снимок, `hwid`, `language` и `paused`. Он не содержит `state.json`, `/var/run`, бинарников и модулей ядра. Подготовка явная: фоновый агент не переписывает дополнительный снимок при каждой проверке.

Проверьте полный список, который показал `sysupgrade -l`, затем обновляйте прошивку штатным способом, с сохранением настроек. OpenWrt объединяет записи из `sysupgrade.conf` и `keep.d`; `-l` показывает предполагаемый состав копии. Дополнительные пользовательские правила либо сохранение всего overlay могут включить больше файлов, поэтому список Luch не ограничивает весь архив OpenWrt. Проект не изменяет ваш `/etc/sysupgrade.conf`. Это поведение описано в [исходниках sysupgrade OpenWrt](https://github.com/openwrt/openwrt/blob/master/package/base-files/files/sbin/sysupgrade).

После загрузки новой прошивки заново запустите актуальную подписанную команду установки Luch. Она выбирает пакет под новую версию и архитектуру и устанавливает соответствующие kernel-зависимости. До запуска клиента сохранённый тонкий снимок восстанавливается автоматически, если рабочего `state.json` нет. Существующие более свежие настройки не заменяются подготовленным снимком.

OpenWrt может восстановить выбранные файлы в каталог `/etc/luch` с правами `0755`. Установщик ужесточает их до `0700` только для полного проверенного набора из подготовленного снимка: с ожидаемым владельцем, закрытыми файлами и совпадающими настройками и идентичностью. Предварительная проверка до остановки клиента ничего не меняет. Посторонние файлы, ссылки, небезопасные права и незавершённое восстановление вызывают отказ; добавлять весь каталог в список sysupgrade для обхода проверки не нужно.

Подготовка не сохраняет программу и не гарантирует перенос старых kernel modules на новую прошивку. Сам sysupgrade выполняет OpenWrt; Luch не обходит его проверки образа. Пустой, ещё не настроенный клиент остаётся ненастроенным после восстановления.

## Границы восстановления и проверки

Пакет `internal/backup` принимает только схему 1 и не более 16 КиБ. Восстановление выполняется после остановки клиента под блокировками установки и рабочих операций. Журнал `/etc/.luch-restore.json` содержит имена собственных директорий и контрольные суммы файлов. При загрузке незавершённая замена возвращает старую директорию либо завершает очистку уже зафиксированной новой. Неожиданные файлы и несовпадение хэшей сохраняются и вызывают понятный отказ; программа не удаляет их как «мусор».

Собственный `keep.d/luch` устанавливается и удаляется только при точном совпадении ожидаемого содержания и владельца. Чужой файл с таким именем не переписывается. Удаление Luch очищает его собственную политику; пользовательские правила sysupgrade сохраняются.

Перед остановкой для удаления проверяются состав, типы, владелец и права настроек и установленных release slots, включая их файлы и init-директории. Проверка повторяется после остановки. Чужие файлы, неожиданные директории под именами настроек и доступные для записи другим пользователям данные сохраняются и вызывают отказ. Очистка неактивных release slots также сохраняет такие данные.

Unit-проверки подтверждают исключение ключей Xray и доверия к прежней загрузке, сохранение HWID/языка/паузы, отказы неверного входа, точный возврат старой директории после ошибки переименования и восстановление после аварийного выхода дочернего процесса в четырёх стадиях. Это не доказательство отключения питания или успешной перепрошивки физического роутера. Полный sysupgrade с повторной подписанной установкой проверяется отдельно на официальном QEMU-образе перед заявлением поддержки сценария.
