## Предварительная проверка загрузки

Перед записью нового DAT меню показывает размер из HTTP Content-Length либо размер локального файла, свободное место в файловой системе хранения и дополнительный требуемый объём. Уже сохранённые базы остаются на диске и уже учтены занятым пространством. Новая копия загружается отдельно; дополнительно сохраняется запас **4 МиБ** под настройки и служебные записи. Проверка повторяется для каждого файла пакетной операции.

Если сервер не указал размер, интерфейс сообщает об этом и показывает доступный предел загрузки. Поток ограничивается фактически свободным объёмом за вычетом запаса и общим пределом 128 МиБ. Превышение удаляет временную копию. Нехватка места получает отдельное русское/английское сообщение с требуемым и свободным объёмами; сохранённые рабочие базы остаются доступны.

Также показывается доступная оперативная память из `/proc/meminfo`; старые ядра используют существующий запасной расчёт MemFree+Buffers+Cached. Предупреждение выводится для файла от **32 МиБ**, неизвестного размера либо файла от **8 МиБ** при общей RAM не более 256 МиБ или малой доступной памяти. Это ориентир для выбора компактной базы, а не точный прогноз пикового потребления Xray. Дополнительного подтверждения не требуется.

Реализация: `internal/routeprofile/resources.go`, вывод меню — `cmd/luch/routing_resources.go`.

## Настоящие прогоны прошивок

| Прошивка | Архитектура | Firewall | RAM роутера | Результат |
| --- | --- | --- | ---: | --- |
| OpenWrt 21.02.7 | x86-64 | fw3 / iptables | 256 МиБ | 7/7 PASS |
| OpenWrt 24.10.8 | x86-64 | fw4 / nftables | 256 МиБ | 7/7 PASS |

Использованы официальные образы, проверенные по SHA-256, с отдельными чистыми дисками QEMU. Корень ext4 расширен до 512 МиБ с проверкой файловой системы. В каждом прогоне работают три машины: испытуемый роутер, внешний VLESS/TLS-сервер и LAN-клиент. Установка выполняется штатным установщиком из локального подписанного тестового пакета. Состояние подписки и правила firewall создаёт настоящий клиент; тестовые помощники их не подставляют.

Для каждой прошивки прошли:

1. Подписанная установка с проверкой всех восьми файлов.
2. Подключение контролируемой HTTPS-подписки через обычное меню, постоянный HWID, настоящий агент/procd/Xray, VLESS/TLS и LAN TCP/UDP/DNS по IPv4/IPv6; исходная блокировка остаётся действующей.
3. Добавление реальной компактной GeoSite v2fly по HTTPS и локального GeoIP DAT через пункт 7. Проверены сообщения о ресурсах, рабочие ext-правила Xray и дальнейший LAN-трафик.
4. Обновление GeoSite до **16 777 216 байт** с предупреждением о RAM. Прежняя версия удалена, осталось ровно два действующих DAT. LAN-трафик и исходные правила продолжают работать.
5. Настоящая перезагрузка с изменением boot_id. Профиль и оба DAT восстановлены, хотя первоначальный локальный файл из `/tmp` уже исчез. Штатная проверка VPN и LAN-пробы проходят.
6. Последовательное удаление источников через меню: файлов становится один, затем **ноль**. В рабочем JSON нет дополнительных ext-правил; исходная маршрутизация продолжает работать.
7. Реальный отказ по месту: поверх уже пустого каталога собственных DAT временно смонтирован изолированный tmpfs объёмом **8 МиБ**. Загрузка файла 16 МиБ отклонена предварительной проверкой, временных файлов не осталось, SHA-256 состояния подписки и рабочего JSON не изменились. LAN-трафик продолжает идти через VPN. После опыта tmpfs размонтирован.

Для обновления до 16 МиБ использован реальный компактный GeoSite с добавленным корректным неизвестным protobuf-полем. Это контролируемая проверка размера, потока загрузки, памяти и обновления; доменные категории сохранены. Предыдущий [аудит восьми реальных баз](EXTRA_ROUTING_AUDIT_2026-11-03.md), включая RuNet Freedom 81,57 МиБ, выполнялся отдельно на настоящем Xray в macOS.

В обоих прогонах использовался один постоянный HWID. Событий OOM в собранной диагностике не обнаружено. Диагностические сэмплы не являются измерением мгновенного пика RAM.

- `go test ./...` с настоящим Xray — PASS.
- `go test -race ./cmd/luch ./internal/routeprofile` — PASS.
- `go vet ./...` — PASS.
- 52 unit-теста инфраструктуры основного QEMU-сценария — PASS.
- Сборки Linux без CGO для amd64, 386, arm64, ARMv5/v6/v7, mips/mipsle softfloat — 8/8 PASS.

В `tools/qemu_production_qualification.py` добавлен адресный режим `--extra-routing-only --memory 256 --extra-geosite FILE`, который выполняет `tools/qemu_extra_routing.py` после базового подключения. Остальные входы — явные targets, candidate, helpers и отдельный output, как в существующем полном сценарии. GeoSite и остальные входные файлы привязаны контрольными суммами; изменившийся вход не считается пройденным испытанием.

Проверки подтверждают указанные две версии и данный сценарий QEMU. Они не заменяют проверку физической модели, всех прошивок или пригодности любой гигантской базы для любого объёма RAM.
